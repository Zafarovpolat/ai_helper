## 1. Краткое резюме и вердикт

**3D-модель полноценно работает прямо в браузере через WebGL**, её реально подключить к распознаванию речи и «заставить говорить» с синхронной артикуляцией губ. Это не эксперимент, а стандартный современный подход: существуют зрелые open-source библиотеки именно под эту задачу.

**Unreal Engine / MetaHuman для веба не нужны.** В браузере они нативно не запускаются — требуется Pixel Streaming: рендер на облачной GPU-машине и трансляция видеопотока. Это означает одну GPU-инстанцию на каждый одновременный экран (аренда порядка $0.5–2+/час), сетевые задержки и дорогую эксплуатацию. Для музейного киоска, работающего весь день на нескольких мониторах, это экономически неоправданно и технически избыточно.

**Настоящее узкое место проекта — не аватар, а качество узбекской речи (STT и TTS).** Реализм 3D решается готовыми компонентами; сложность — в языке. Решения ниже выстроены вокруг этого приоритета.

**Рекомендуемый путь:** стилизованный 3D-гид в браузере на бесплатном/MIT-стеке (Путь 1) как основа, с возможностью апгрейда до реалистичного варианта (Путь 2) без переписывания архитектуры.

## 2. Контекст задачи

Из презентации заказчика:

- **Продукт:** ИИ-аватар — голосовой гид по истории Узбекистана; полноэкранное веб-приложение на мониторах (2-й этаж музея, киоск-режим).
- **Три компонента:** голосовой помощник (STT/TTS), ИИ-аватар (визуал + липсинк), база знаний (RAG).
- **Сценарий:** обнаружение присутствия → потоковое распознавание речи → поиск по базе знаний → потоковая озвучка с синхронной мимикой.
- **Точность:** LLM отвечает **строго из загруженной базы знаний**, проверенной историком (учебники, музейные каталоги; Амир Темур, Улугбек, Шёлковый путь), без домыслов.
- **Скорость:** потоковый STT, потоковый TTS (речь с первых слов), кэш частых вопросов, fallback при обрыве сети.
- **Обновления:** правки на сервере распространяются на все экраны.
- **Заложенные заказчиком варианты аватара:** 2D видео-аватар (дёшево/быстро), стилизованная иллюстрация (баланс), 3D-аватар (премиум). Рекомендация в презентации — «рассказчик» в национальной одежде.
- **Лицензирование:** по экранам, с онлайн-проверкой ключа.
- **Роадмап (из презентации):** база знаний 2–3 нед., прототип «голос + RAG» 2–4 нед., дизайн аватара 3–5 нед., интеграция в киоск 1–2 нед., пилот 1–2 нед., масштабирование.

## 3. Анализ конкурента

`tarix-yordamchisi` — ориентир «сделать, но лучше». Типовые слабые места и наши улучшения:

| Слабость конкурента | Наше улучшение |
|---|---|
| Браузерный Web Speech API — плохо понимает узбекский, требует интернет и доступ к микрофону | Серверный **Whisper / Azure STT** с реальной поддержкой узбекского |
| Обычно только текст/2D-картинка, без живого аватара | **3D-аватар с липсинком** и мимикой |
| LLM отвечает «из головы» → фактические ошибки | **RAG**: ответы только из проверенной историком базы |
| Нет киоск-режима, кэша, fallback | Полноэкранный киоск, кэш топ-вопросов, оффлайн-fallback |

## 4. Архитектура решения (сквозной конвейер)

```
[Присутствие]          камера/датчик → «разбудить» аватар, приветствие
      ↓
[Речь → текст (STT)]   потоковое распознавание (Azure uz-UZ / Whisper)
      ↓
[Мозг: LLM + RAG]      вопрос → векторный поиск по базе → ответ строго по источникам
      ↓
[Текст → речь (TTS)]   потоковая озвучка с первых слов (Azure uz-UZ)
      ↓
[Липсинк]              анализ аудио → визема → форма рта
      ↓
[3D-аватар в браузере] WebGL/three.js: морфы губ + мимика + жесты
```

Дополнительно: **кэш** частых Q&A (мгновенный ответ без LLM), **fallback** на заготовленные ответы при обрыве сети, **центральный сервер** базы знаний с пушем обновлений на все экраны.

## 5. Общий фундамент

Эти слои **не зависят от выбора аватара** и одинаковы для обоих путей. Они решают главную боль (узбекский язык) и достоверность.

### 5.1. Речь → текст (STT)

| Компонент | Выбор | Роль |
|---|---|---|
| Основной | **Azure Speech STT, локаль `uz-UZ`** | Потоковое распознавание узбекского |
| Альтернатива | OpenAI `gpt-4o-transcribe` / `whisper-1` | Узбекский поддержан; можно self-host `faster-whisper`/`whisper.cpp` бесплатно |
| Присутствие | Камера + лёгкая модель детекции или PIR-датчик | «Разбудить» аватар |

### 5.2. Текст → речь (TTS) — критический слой

| Решение | Узбекский | Заметки |
|---|---|---|
| **Azure TTS (`uz-UZ` neural)** | **Да** | Лучший единый вендор; узбекские нейроголоса + русский |
| ElevenLabs | **Нет** | Русский есть, узбекского нет |
| Google Cloud TTS | Скорее нет | Узбекский не подтверждён |
| Meta MMS (`mms-tts-uzb`) | Да, open-source | Лицензия похоже **CC-BY-NC (некоммерческая)** — проверить |
| Mohir.ai | Локальный узб. провайдер | Не проверено вживую — уточнить |

> **Проверить до контракта:** точные имена узбекских нейроголосов Azure и актуальный прайс TTS.

### 5.3. Липсинк (общий, ключевое решение)

- **wawa-lipsync** (MIT) — анализ амплитуды/частот аудио через Web Audio API `AnalyserNode`, виземы в реальном времени.
- **Не зависит от языка вообще** — работает с узбекским, русским, любым.
- Это снимает проблему, что движки виземы (встроенный в TalkingHead — только en/de/fr/fi/lt; Azure-виземы зависят от локали) **не покрывают узбекский**.

### 5.4. Мозг: LLM + RAG (достоверность)

| Компонент | Выбор |
|---|---|
| LLM | Claude / GPT |
| Векторная БД | **pgvector** (в Postgres) или **Qdrant** |
| Пайплайн | вопрос → эмбеддинг → векторный поиск по проверенной базе → топ-фрагменты → LLM формулирует ответ **строго по ним** |
| Кэш | Топ-вопросы (Redis/таблица) — мгновенный ответ без вызова LLM |
| Наполнение | сбор → чанки → векторизация → **проверка историком** → публикация |

### 5.5. Инфраструктура / киоск

- Единый backend: прокси STT + RAG + прокси TTS + БД знаний.
- Полноэкранный веб (Fullscreen API), attract-loop при отсутствии посетителей.
- Обновление базы на сервере → пуш на все экраны (WebSocket/поллинг).
- **Fallback:** локальный кэш + заготовленные ответы при обрыве сети.

## 6. Путь 1 — простой (MVP / оптимальный)

**Идея:** стилизованный 3D-«рассказчик» в национальной одежде, живёт прямо в браузере (WebGL), максимум готовых бесплатных компонентов. Это ровно то, что заказчик в презентации назвал «оптимальным балансом».

### 6.1. Стек по слоям

| Слой | Технология | Лицензия | Роль |
|---|---|---|---|
| Каркас | React 18+ / **Vite** / TypeScript | MIT | Приложение, киоск-режим |
| 3D-движок | **three.js** (r180) | MIT | WebGL-рендер |
| React-обёртка | **@react-three/fiber** + **@react-three/drei** | MIT | Декларативная сцена, загрузка GLB, свет, отладка |
| Аватар | **Ready Player Me** (`.glb`) | Free | Стилизованный гид, костюм/орнамент |
| Виземы | URL-параметр `?morphTargets=ARKit,Oculus%20Visemes` | — | Блендшейпы губ приходят вместе с моделью |
| Анимация | **TalkingHead** (`@met4citizen/talkinghead`) | MIT | Губы, моргание, взгляд, жесты, поворот головы |
| Липсинк | **wawa-lipsync** | MIT | Синхронизация рта с аудио, язык-независимо |
| Речь/мозг | Azure STT+TTS · LLM+RAG | — | См. раздел 5 |

### 6.2. Как работает (сквозной поток)

```
Человек подошёл
   → камера будит аватар, приветствие
Человек говорит (узбекский)
   → аудио стримится в Azure STT (uz-UZ) → текст
   → RAG: векторный поиск по проверенной базе → топ-фрагменты
   → LLM формулирует ответ СТРОГО по источникам
   → текст стримится в Azure TTS (uz-UZ) → аудиопоток
   → wawa-lipsync анализирует аудио → виземы
   → three.js рендерит аватар с синхронной артикуляцией и мимикой
```

### 6.3. Порядок сборки (пошагово)

1. Каркас: `Vite + React + TypeScript`, полноэкранный layout, attract-loop.
2. 3D-сцена: `three.js` + `@react-three/fiber` + `@react-three/drei`, свет, камера.
3. Аватар: сгенерировать в Ready Player Me с параметром `morphTargets=ARKit,Oculus Visemes`, загрузить `.glb` в сцену.
4. Анимация: подключить `TalkingHead` — idle-движения (дыхание, моргание, микродвижения), чтобы аватар не выглядел «замороженным».
5. Липсинк: `wawa-lipsync` поверх аудиопотока TTS → драйв морфов губ.
6. Речь: backend-прокси к Azure STT (uz-UZ) и Azure TTS (uz-UZ, потоково).
7. Мозг: RAG на pgvector/Qdrant + LLM; ответ строго по найденным фрагментам; кэш топ-вопросов.
8. Киоск: пуш обновлений базы на экраны, fallback при обрыве сети, лицензионный ключ по экрану.

### 6.4. Плюсы

- Почти весь стек — **MIT/бесплатный**; платишь только за облачные вызовы.
- **Работает в браузере без Unreal и GPU-стриминга**, на обычном железе.
- Быстрая разработка (**недели, не месяцы**).
- wawa-lipsync снимает узбекскую липсинк-проблему.
- Нет поминутной оплаты за аватар; полный контроль; лёгкое масштабирование на экраны.

### 6.5. Минусы / риски

- Вид **стилизованный**, не фотореализм (но это и есть заявленный «оптимальный баланс»).
- Качество узбекского TTS = зависимость от Azure → проверить голоса.
- Требуется аккуратная сборка RAG и вычитка историком.

### 6.6. Стоимость

- **Софт:** $0 (MIT/free).
- **Облако:** STT ~$0.006/мин (Whisper) или тариф Azure · TTS Azure ~$16/1M символов *(оценка, уточнить)* · LLM — по токенам · хостинг сервера.
- **Разработка:** низкая/средняя.

## 7. Путь 2 — сложный (премиум-реализм)

**Идея:** максимальный визуальный «вау» — реалистичный человек / историческая личность. Речевой фундамент (раздел 5) тот же; меняется **только слой аватара**. Внутри — три под-варианта по возрастанию сложности.

### 7.1. Вариант 2A — Avaturn (реалистичный 3D в том же браузерном стеке)

*Самый разумный из «сложных».*

| Параметр | Значение |
|---|---|
| Что | Реалистичный 3D-аватар (`.glb` с ARKit-блендшейпами) из фото/селфи |
| Стек | Тот же: React + three.js + TalkingHead + **wawa-lipsync** |
| Плюс | Полуреалистичный 3D-человек, всё ещё **в браузере, без GPU-стриминга** |
| Минус | Возможен «эффект зловещей долины»; зависимость от Avaturn; вопрос достоверности лица исторической личности |

### 7.2. Вариант 2B — 2D фотореалистичный говорящий портрет

*Часто честнее для исторической личности.*

| Параметр | Значение |
|---|---|
| Почему | От Амира Темура остались лишь портреты/статуи — **2D-оживление портрета научно защитимее**, чем 3D-фантазия лица |
| Real-time | **D-ID**, **HeyGen** — поминутная оплата, watermark на триале |
| Open-source (pre-render) | **LivePortrait**, **SadTalker**, **Hallo**, **EMO** — заранее рендерим ответы / ключевые фразы |
| Плюс | Выглядит «живым» человеком; open-source бесплатен |
| Минус | Real-time SaaS **поминутно** (дорого для киоска); pre-render не даёт свободный диалог; open-source требует своих GPU |

### 7.3. Вариант 2C — MetaHuman / Unreal Engine

*Максимум реализма — не рекомендуется.*

| Параметр | Значение |
|---|---|
| Проблема | В браузере **нативно не работает** → требуется **Pixel Streaming** |
| Инфраструктура | **Одна облачная GPU на каждый одновременный экран** (~$0.5–2+/час), сетевые задержки, сложная эксплуатация |
| Вердикт | Избыточно и дорого для веб-киоска. Для веба Unreal не нужен |

### 7.4. Плюсы пути 2

- Максимальный реализм и «вау»-эффект.

### 7.5. Минусы / риски пути 2

- Дороже в разработке **и** эксплуатации.
- Риск достоверности лица исторической личности (научный/этический).
- Возможная вендор-зависимость и поминутная оплата.
- «Эффект зловещей долины» у реалистичного 3D (2A/2C).

### 7.6. Стоимость

От средней (Avaturn) до высокой (MetaHuman + Pixel Streaming + аренда GPU).

## 9. Готовые решения (SaaS): строить или купить

Коробочные «говорящие аватары» дают быстрый старт, но с оговоркой:

- **HeyGen, D-ID** — real-time 2D-фотореалистичные аватары, поминутная оплата.
- **Tavus** — реалистичный человек, база знаний, встраивается.
- **Simli** — задержка <300 мс, свои STT/LLM/TTS, есть бесплатный тариф.
- **Convai** — разговорные 3D-персонажи.
- **Avaturn** — реалистичный 3D из селфи, работает в браузере.

> **Ключевая оговорка для музея:** почти все берут **поминутную плату**. Для киоска, работающего весь день на нескольких экранах, это дорого и создаёт зависимость от вендора. Для always-on предпочтительнее **своё решение на open-source**; SaaS — максимум для быстрого прототипа/демо.

## 11. Итоговая рекомендация и спецификация

**Старт — Путь 1** (стилизованный 3D-рассказчик): закрывает всё ТЗ, дёшево, современно, максимально на бесплатном/MIT, работает в браузере без Unreal.

**Апгрейд во 2-й фазе — Путь 2A (Avaturn) или 2B (2D-портрет)**, если заказчик захочет «премиум»-реализм. **MetaHuman/Unreal (2C) не брать** для веб-киоска.

Речевой фундамент общий, поэтому переход с Пути 1 на 2A/2B меняет только слой аватара, а не всю архитектуру — можно стартовать быстро и апгрейдить без переписывания.

**Спецификация рекомендуемого стека (Путь 1):**

- Frontend: React 18+ / Vite / TypeScript
- 3D: three.js + @react-three/fiber + @react-three/drei
- Аватар: Ready Player Me (`.glb`, `morphTargets=ARKit,Oculus Visemes`)
- Анимация: TalkingHead (MIT)
- Липсинк: **wawa-lipsync** (MIT, язык-независимо)
- STT: **Azure Speech uz-UZ** (альтернатива: Whisper / gpt-4o-transcribe, self-host бесплатно)
- TTS: **Azure Speech uz-UZ** (+ ru-RU)
- Мозг: LLM (Claude/GPT) + RAG на pgvector/Qdrant, ответ строго из проверенной базы
- Киоск: полноэкранный веб, кэш топ-вопросов, fallback при обрыве сети, лицензионный ключ по экрану

| 1 | База знаний: сбор → чанки → векторизация → проверка историком | 2–3 нед. |
| 2 | Прототип «голос + RAG» (STT → RAG → TTS) | 2–4 нед. |
| 3 | Дизайн и сборка аватара (RPM «рассказчик» + анимация + липсинк) | 3–5 нед. |
| 4 | Интеграция в киоск (полноэкран, кэш, fallback, лицензия) | 1–2 нед. |
| 5 | Пилот на площадке | 1–2 нед. |
| 6 | Масштабирование на экраны | — |

## 13. Риски и их снижение

| Риск | Снижение |
|---|---|
| Узбекский TTS/STT — главный дефицит | Ставка на **Azure** (сильнейший единый вендор); заранее протестировать голоса |
| Виземы не покрывают узбекский | **wawa-lipsync** (амплитудный, язык-независимый) |
| LLM выдумывает исторические факты | Жёсткий **RAG** + проверка корпуса историком |
| Обрыв сети в киоске | Локальный кэш + заготовленные ответы (fallback) |
| Достоверность лица истор. личности (Путь 2) | Предпочесть стилизацию (Путь 1) или 2D-оживление портрета (2B) |
| Вендор-локин / поминутная оплата SaaS | Своё open-source решение для always-on |
